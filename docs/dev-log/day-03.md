# Day 3 — 대화 기록과 초기화 구현

## 오늘 목표
이전 질문과 답변을 다음 API 요청에 함께 전달해 대화 맥락을 유지한다.

## 구현한 것
- `ask_llm()`이 질문 문자열 대신 메시지 리스트를 받도록 수정했다.
- 사용자 질문을 `user`, 모델 답변을 `assistant` 역할로 저장했다.
- `reset` 입력 시 system 메시지만 남기고 대화를 초기화했다.
- 초기화와 빈 입력은 API를 호출하지 않도록 처리했다.

## 배운 개념
`messages`는 메시지 딕셔너리들을 담는 리스트다. 각 딕셔너리의 `role`은 발화자의 역할을, `content`는 내용을 나타낸다.

API 응답 객체와 `answer`는 다르다. `ask_llm()`은 응답에서 답변 텍스트만 꺼내 반환하므로 `answer`는 문자열이다.

`append()`가 답변을 자동으로 인식하는 것은 아니다. 내가 `role: assistant`를 지정한 딕셔너리를 추가하기 때문에 이전 AI 답변으로 전달된다.

모델이 이전 대화를 참고할 수 있는 이유는 프로그램이 저장한 기록을 다음 요청에 다시 보내기 때문이다.

## 실행 검증
- 세종대왕의 업적을 질문한 뒤 “응, 더 자세히 설명해줘”라고 입력하자 같은 주제로 설명을 이어갔다.
- Python 설명을 받은 뒤 `reset`을 입력하자 초기화 안내만 출력됐다.
- 초기화 후 “응 만들어줘”라고 입력하자 이전 제안에 이어 답하지 않고 무엇을 만들지 다시 물었다.
- `exit` 입력으로 정상 종료됐다.

이번 검증은 대화 맥락 유지와 초기화 동작에 대한 것이며, 답변 내용의 사실 정확성은 별도로 검증하지 않았다.

## 관찰한 점
세종대왕 대화에서 입력 토큰이 36에서 525로 증가했다. 이전 질문과 답변이 다음 요청에 포함되므로 대화가 길어질수록 입력 토큰과 비용이 증가할 수 있다.

## 설계 결정
현재는 Python 리스트로 대화 기록을 관리한다. 메시지가 쌓이고 전달되는 원리를 직접 확인할 수 있고, 오늘 범위에서는 별도 저장소가 필요하지 않기 때문이다.

초기화할 때는 `messages[:1]`로 첫 번째 system 메시지를 유지한다. 이 방식은 system 메시지가 항상 첫 번째에 있다는 현재 구조를 전제로 한다.

## 오류와 한계
- 공유한 실행 결과에서는 실행 오류가 발생하지 않았다.
- 기록은 메모리에만 있어 프로그램을 종료하면 사라진다.
- 대화 길이를 제한하지 않아 기록이 계속 늘어난다.
- API 실패 처리는 아직 구현하지 않았다.
